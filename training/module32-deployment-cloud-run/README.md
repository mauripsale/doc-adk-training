### From Validated Prototype to Serverless Production

In Module 31, you built `support-ops-agent`, verified stateful tool execution locally, and proved its quality with `agents-cli eval run`. Now you are ready for **Phases 5 and 6 of the `agents-cli` lifecycle**: upgrading your prototype in place for **Google Cloud Run** (`scaffold enhance`) and rolling out a live, authenticated HTTPS container (`agents-cli deploy`).

Google Cloud Run is a fully managed serverless container runtime that pairs naturally with ADK agents:
* **Zero Server Administration:** Provide a `Dockerfile` (already generated by `agents-cli`), and Cloud Run manages TLS certificates, load balancing, health checks, and revision rollouts.
* **Dual-Protocol Serving Out of the Box:** The scaffolded `uvicorn app.fast_api_app:app` container simultaneously serves ADK's native streaming routes (`/run_sse`, `/apps/app/...`) **and** the Agent-to-Agent (A2A) surface (`/a2a/app/.well-known/agent-card.json` + JSON-RPC) on port `8080`.
* **Pay-Per-Request & Revision Traffic Control:** Dev services scale to zero when idle (`--min-instances 0`), while production services pin warm instances and support instant traffic shifting across immutable revisions.

### Upgrading a Prototype In Place with `agents-cli scaffold enhance`

![Automated Cloud Run Deployment Pipeline (Light)](img/cloud-run-deployment-pipeline-light.webp#gh-light-mode-only)
![Automated Cloud Run Deployment Pipeline (Dark)](img/cloud-run-deployment-pipeline-dark.webp#gh-dark-mode-only)
*Figure: Automated Cloud Run promotion pipeline — in-place IaC enhancement, Cloud Build image compilation, Artifact Registry storage, and Cloud Run revision rollout.*

Because you started with `--prototype` in Module 31, adding Cloud Run infrastructure requires zero code rewrites. Running `scaffold enhance` from inside `support-ops-agent/` merges production assets in place **while preserving `app/agent.py`, `.env`, `GEMINI.md`, and `tests/eval/` untouched**:

```bash
agents-cli scaffold enhance . \
  --deployment-target cloud_run \
  --cicd-runner github_actions \
  --region us-central1
```

#### What `scaffold enhance` Adds to Your Project
* **Updated `agents-cli-manifest.yaml`:** Records `deployment_target: cloud_run`, `cicd_runner: github_actions`, and `region: us-central1` so `agents-cli deploy` knows how to package and target the service.
* **Modular Terraform IaC (`deployment/terraform/`):**
  * `deployment/terraform/single-project/` (`service.tf`, `iam.tf`, `storage.tf`) — Single-project Cloud Run v2 service, Artifact Registry, least-privilege `app_sa` runtime service account, and telemetry bindings (usable via `agents-cli infra single-project --apply`).
  * `deployment/terraform/cicd/` & `deployment/terraform/shared/` — Multi-environment staging-to-production promotion with `cicd_runner_sa`, Workload Identity Federation (WIF), and optional persistent **Cloud SQL for PostgreSQL 15** session storage when `--session-type cloud_sql` is selected.
* **CI/CD Pipelines (`.github/workflows/` or `.cloudbuild/`):** Automated lint, evaluation gate, staging deploy, load test, and human-approved production rollout workflows.
* **Load Testing Suite (`tests/load_test/load_test.py`):** Pre-configured Locust harness for stress-testing concurrency and memory ceilings before production launch.

### Sizing, Security & Secrets Flags on `agents-cli deploy`

For rapid dev and staging deployments, `agents-cli deploy` works standalone (no prior `terraform apply` required) and exposes fine-grained sizing and security flags:

| Flag | Default (`agents-cli deploy`) | Production Guidance & Coupling Rules |
| :--- | :--- | :--- |
| `--cpu` | `1` | Container runs a single async Uvicorn process; scale **out** via concurrency and instances first, raising `--cpu` only when profiling shows real CPU saturation rather than LLM wait time. |
| `--memory` | `4Gi` | **Memory bounds concurrency.** Each concurrent request holds its prompt history, tool payloads, and stream buffer in RAM (`peak ≈ base + concurrency × per-request RAM`). Never raise `--concurrency` without checking `--memory`. |
| `--concurrency` | `8` | Conservative default protecting RAG/multimodal agents from OOM. Lightweight tool-calling agents can tune to `16–32` using `tests/load_test/load_test.py`. |
| `--min-instances` | `0` (`1` in `service.tf`) | `0` avoids idle dev cost; pass `--min-instances 1` (default in generated `service.tf`) to eliminate cold starts for latency-sensitive or Live API agents. |
| `--max-instances` | `10` | Horizontal scaling cap protecting downstream APIs and model quotas. |
| `--timeout` | `300` (seconds, max `3600`) | Increase to `--timeout 3600` for long-running research workflows or bidirectional **Live / voice** WebSocket sessions. |
| `--iap` | Off | Enables **Identity-Aware Proxy** on Cloud Run so only authorized Google Workspace identities can reach the service without custom auth code. |
| `--secrets` | — | Mounts GCP Secret Manager secrets as env vars (e.g., `--secrets "WEBHOOK_TOKEN=prod-webhook:latest"`); never commit production API secrets into `.env`. |

### Separating Infrastructure Region (`DEPLOY_REGION`) from Model Location (`GOOGLE_CLOUD_LOCATION=global`)

One of the most important operational distinctions on Google Cloud is separating **where your container runs** from **where your Gemini model endpoint is served**:

* **`DEPLOY_REGION` (`--region us-central1`):** Cloud Run services, Cloud Build workers, and Artifact Registry repositories are regional resources and require a concrete region such as `us-central1` or `europe-west1`.
* **`GOOGLE_CLOUD_LOCATION=global`:** On Gemini Enterprise / Vertex AI (`GOOGLE_GENAI_USE_ENTERPRISE=1`), **`gemini-3.8-flash`** is served on the **`global`** endpoint. Passing `--env-vars "GOOGLE_GENAI_USE_ENTERPRISE=1,GOOGLE_CLOUD_LOCATION=global"` ensures the running Cloud Run container routes model inference to `global` rather than defaulting to `us-central1` (which would cause runtime `404 NOT_FOUND` model errors):

```bash
export GOOGLE_CLOUD_PROJECT="your-project-id"
export DEPLOY_REGION="us-central1"

agents-cli deploy \
  --project "$GOOGLE_CLOUD_PROJECT" \
  --region "$DEPLOY_REGION" \
  --env-vars "GOOGLE_GENAI_USE_ENTERPRISE=1,GOOGLE_CLOUD_LOCATION=global" \
  --no-confirm-project
```

### Testing & Evaluating Live Cloud Run Endpoints

By default, Cloud Run services deployed by `agents-cli` enforce IAM authentication (`--no-allow-unauthenticated`). Rather than manually crafting `curl` headers and minting short-lived identity tokens, `agents-cli` natively authenticates, manages sessions, and speaks **both** protocols against your `--url`:

1. **Test the Built-In A2A Endpoint (`--mode a2a`):**
   Discovers `/a2a/app/.well-known/agent-card.json` and streams JSON-RPC tasks over HTTPS:
   ```bash
   agents-cli run "Investigate ticket TCK-1042 and check SLA." \
     --url "$SERVICE_URL" \
     --mode a2a
   ```
2. **Test the Native ADK Streaming Endpoint (`--mode adk`):**
   Creates an ADK session and streams Server-Sent Events (`/run_sse`) against `--app-name app`:
   ```bash
   agents-cli run "Check ticket TCK-2088." \
     --url "$SERVICE_URL" \
     --mode adk \
     --app-name app
   ```
3. **Run Remote Cloud Evaluation (`eval generate --url` + `eval grade`):**
   Validates the live Cloud Run container end-to-end against `tests/eval/datasets/basic-dataset.json`:
   ```bash
   agents-cli eval generate --url "$SERVICE_URL" --app-name app && agents-cli eval grade
   ```

### Key Takeaways
* **In-Place Promotion (`scaffold enhance`):** `agents-cli scaffold enhance . --deployment-target cloud_run` upgrades a validated prototype with Terraform IaC (`deployment/terraform/`), CI/CD pipelines, and Locust load tests without touching `app/agent.py` or `.env`.
* **Coupled Sizing:** Memory (`--memory`, default `4Gi`) bounds `--concurrency` (default `8`); scale `--concurrency`, `--memory`, and `--max-instances` together using `tests/load_test/`, and set `--min-instances 1` (plus `--timeout 3600` for Live voice agents) when cold starts are unacceptable.
* **Region Separation:** Always pair regional Cloud Run infrastructure (`--region us-central1`) with `--env-vars "GOOGLE_GENAI_USE_ENTERPRISE=1,GOOGLE_CLOUD_LOCATION=global"` for `gemini-3.8-flash`.
* **Live Dual-Protocol Verification:** Use `agents-cli run --url "$SERVICE_URL" --mode [a2a|adk]` and `agents-cli eval generate --url "$SERVICE_URL" --app-name app && agents-cli eval grade` to verify authenticated Cloud Run deployments end-to-end.
